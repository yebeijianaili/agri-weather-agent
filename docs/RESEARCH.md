# 农田气象时序分析 Agent：前期调研报告

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.2.0 |
| 调研日期 | 2026-08-22 |
| 研究对象 | 农田日尺度温度、降水、太阳辐射与湿度时序 |
| 目标用户 | 农业生产管理者、农业数据分析人员、项目验收人员、平台运维人员 |
| 项目边界 | 数据导入、质量控制、统计分析、风险识别、Agent 解读、结果导出与审计闭环 |

## 1. 调研目标

本项目需要回答的不是“展示几张图”，而是以下可验证问题：

1. 数据是否完整、可信，哪些记录被修正、标记或排除？
2. 每个地块在春、夏、秋、冬的温度、降水、光照特征分别是什么？
3. 指标相对历史或本期基线是否存在趋势、异常和农业环境风险？
4. 用户能否从原始数据一路追溯到图表、结论、风险证据和导出文件？
5. 非专业用户能否用自然语言提问，并获得带数值证据、时间范围和地块范围的答复？

因此，产品采用“数据进入—质量检查—指标计算—风险识别—Agent 解释—报告导出—历史复核”的闭环，而不是单次静态可视化。

## 2. 农业气象业务口径

### 2.1 为什么选择四类变量

| 变量 | 农业环境意义 | 本项目用途 | 不做的过度推断 |
|---|---|---|---|
| 温度 | 影响作物发育速度、蒸散和热/冷胁迫 | 季节均值、极值、趋势、高低温事件 | 缺少作物品种和生育期时，不直接给出产量结论 |
| 降水 | 影响土壤水分补给、田间作业和涝旱风险 | 累计降水、雨日、强降雨、连续无有效降水日 | 缺少灌溉、土壤和径流数据时，不等同于土壤干旱 |
| 太阳辐射 | 表征可利用光能并影响能量平衡 | 平均光照、低光照连续事件、季节对比 | 缺少冠层和光合参数时，不直接估算生物量 |
| 相对湿度 | 可帮助解释高湿环境和蒸散背景 | 概览、异常校验、Agent 上下文 | 缺少叶面湿度与病原数据时，不直接诊断病害 |

FAO Irrigation and Drainage Paper 56 使用太阳辐射、温度、湿度等变量描述参考蒸散相关方法。本项目保留这些变量的可扩展性，但当前核心交付是可解释的时序统计，不把参考蒸散或作物需水量伪装成已完成能力。

### 2.2 数据粒度和单位

- 一条观测代表一个分析对象（自有地块或外部网格）一天的聚合记录。
- `timestamp` 采用 ISO 8601 日期；平台业务时间按 `Asia/Shanghai`，默认 NASA POWER 日数据使用来源元数据声明的本地太阳时 `LST`。
- `temperature_c` 是日平均气温，单位 °C。
- `precipitation_mm` 是该日累计降水量，单位 mm/day。
- `solar_radiation_wm2` 是全天平均短波太阳辐射通量，单位 W/m²。
- `humidity_pct` 是日平均相对湿度，单位 %。
- 如需与 FAO-56 常用的日总辐射量比较，可用：`MJ/m²/day = W/m² × 0.0864`。NASA POWER 的 `ALLSKY_SFC_SW_DWN` 原始单位是 MJ/m²/day，获取脚本显式按 `×1,000,000÷86,400` 转为平台日均 W/m²，并在 provenance 中记录公式；普通用户 CSV 不做未声明的隐式换算。

### 2.2.1 正式数据源选择与落地

本期默认数据采用 NASA Langley Research Center POWER Project 的 `POWER Daily API v2.9.7`，而不是随机样例作为页面主数据。选择原因是：接口公开、参数/单位可机读、查询 URL 可复现，且能提供本项目需要的温度、降水、太阳辐射和相对湿度日值。

| 项目 | 落地值 |
|---|---|
| 数据集 | `NASA/POWER Source Native Resolution Daily Data` |
| 参数 | `T2M`、`PRECTOTCORR`、`ALLSKY_SFC_SW_DWN`、`RH2M` |
| 空间点 | 深圳光明 `(22.7489,113.9359)`、龙岗 `(22.7215,114.2469)`、大鹏 `(22.5963,114.4797)` |
| 时段 | 2024-01-01 至 2024-12-31，366 日 |
| 规模 | 三网格各 366 条，共 **1,098 条** |
| 可追溯物 | 三个完整 JSON 来源快照、三个查询 URL、参数/单位、响应坐标、获取时间、各文件 SHA-256、归一化 CSV SHA-256；provenance 明确区分 `normalized_json_snapshot` 与 `http_response_body` |

POWER 返回的是指定坐标对应的网格化卫星/再分析产品，不是地面站或田间传感器实测。它适合作为可追溯的工程演示和区域背景数据；用于实际农事决策时仍需与现场观测、土壤、作物和管理信息联合复核。

### 2.3 季节划分假设

首版采用北半球气象季节，规则固定且在报告中公开：

| 季节 | 月份 | `season_year` 规则 |
|---|---|---|
| 春季 | 3、4、5 月 | 等于日历年 |
| 夏季 | 6、7、8 月 | 等于日历年 |
| 秋季 | 9、10、11 月 | 等于日历年 |
| 冬季 | 12、1、2 月 | 12 月归入下一年，例如 2025-12 至 2026-02 为冬季 2026 |

这一划分便于验收和跨地块对比，但并不等同于作物生育季。后续如接入区域、作物和物候配置，应允许自定义季节窗口；首版导出必须记录所用规则，避免跨年冬季被拆成两段。

### 2.4 核心统计指标

| 指标 | 计算口径 | 最小样本/注意事项 |
|---|---|---|
| 平均温度 | 有效日平均温度算术平均 | 同时输出有效天数和覆盖率 |
| 最高/最低温度 | 有效日平均温度的最大/最小值 | 名称明确为“日均温最高/最低”，不冒充日极值 |
| 温度趋势 | 对日期序号做一元线性回归，输出 °C/30 天 | 少于 30 个有效日时标记“样本不足” |
| 累计降水 | 有效日降水量求和 | 缺测日不按 0 mm 处理 |
| 雨日数 | 日降水量 ≥ 0.1 mm 的天数 | 阈值写入报告元数据 |
| 最长连续干日 | 连续日降水量 < 1.0 mm 的最大长度 | 与 ETCCDI 的 CDD 阈值惯例保持一致；缺测会中断序列 |
| 平均光照 | 有效日平均辐射的算术平均 | 同时可导出等价 MJ/m²/day |
| 低光照日数 | 日平均辐射 < 100 W/m² 的天数 | 是项目默认规则，不是通用作物阈值 |
| 数据覆盖率 | 有效观测日数 / 时间范围内预期日数 | 按地块、变量分别计算 |
| 同比/环比 | 同地块、同口径相邻季节或同季节上年比较 | 无可比基线时显示“暂无基线”，不输出 0% |

### 2.5 异常检测

统计异常和业务风险分开表达：

1. **统计异常**：同一地块、同一季节、同一变量在样本数不少于 8 时使用 IQR 法，低界为 `Q1 - 1.5×IQR`，高界为 `Q3 + 1.5×IQR`。
2. **硬边界异常**：违反物理/业务合理范围的数据直接标记为 `out_of_range`。
3. **业务风险**：根据可配置阈值和持续时间产生事件，必须带起止日期、命中值、阈值与地块。
4. IQR 为 0 时不通过除零或任意放大制造异常；仅保留硬边界和业务规则判断。
5. 缺测、插补值和疑似异常值均要保留质量标签，Agent 回答中不得隐藏其影响。

## 3. 风险规则调研与首版阈值

下表是为了演示和工程验收而设定的**可配置项目默认值**，不是地区通用农艺处方。真实生产部署需结合当地气候、作物、品种、生育阶段和管理措施校准。

| 风险代码 | 默认判定 | 默认等级 | 证据输出 |
|---|---|---|---|
| `HEAT_DAY` | `temperature_c ≥ 35°C` | 中 | 日期、温度、阈值 |
| `HEAT_STREAK` | 连续 3 日 `temperature_c ≥ 35°C` | 高 | 起止日期、持续天数、峰值 |
| `COLD_DAY` | `temperature_c ≤ 0°C` | 高 | 日期、温度、阈值 |
| `HEAVY_RAIN` | `precipitation_mm ≥ 50 mm/day` | 高 | 日期、日降水量、阈值 |
| `DRY_SPELL` | 连续 7 日 `precipitation_mm < 1 mm/day` | 中 | 起止日期、持续天数、期间累计降水 |
| `LOW_LIGHT_STREAK` | 连续 3 日 `solar_radiation_wm2 < 100 W/m²` | 中 | 起止日期、持续天数、均值 |
| `TEMP_SWING` | 相邻有效日温差绝对值 ≥ 10°C | 中 | 两日日期、温度及差值 |

风险事件去重规则：同一地块、同一代码、时间相交或连续的命中合并为一个事件；事件再次分析时以 `analysis_id + plot_id + risk_code + start_date + end_date` 确保幂等。

## 4. 数据质量调研与判定规则

### 4.1 分层质量控制

| 层级 | 检查 | 处理 |
|---|---|---|
| 文件级 | 扩展名、编码、大小、空文件、表头 | 文件失败时拒绝导入并给出可操作错误 |
| 结构级 | 必填列、未知列、列名重复 | 缺必填列拒绝；未知列保留警告但不参与计算 |
| 行级 | 日期/数值解析、必填缺失、地块编号 | 无效行进入拒绝计数，不污染有效数据 |
| 语义级 | 合理范围、负降水、湿度越界 | 标为 `suspect` 或 `rejected`，记录原因码 |
| 时序级 | 重复、日期间断、倒序、覆盖率 | 重复按策略处理；间断纳入质量报告 |
| 统计级 | IQR 异常、突变 | 标记但不自动删除，供用户复核 |

### 4.2 合理范围

| 字段 | 首版硬边界 | 越界处理 |
|---|---|---|
| `temperature_c` | -50 至 60 °C | 标记 `out_of_range`，不参与默认聚合 |
| `precipitation_mm` | 0 至 500 mm/day | 负值拒绝；超上限标记并排除 |
| `solar_radiation_wm2` | 0 至 1400 W/m² | 负值或超上限标记并排除 |
| `humidity_pct` | 0 至 100% | 越界标记并排除该变量值 |

范围采用宽松的工程合理性检查，避免把少见但真实的极端事件直接删除。任何自动排除都必须在质量摘要中显示记录数和原因。

### 4.3 重复与缺失

- 业务唯一键为 `(plot_id, timestamp)`。
- 同一批次完全相同的重复行保留第一条并计数；关键值冲突的重复行标记 `duplicate_conflict`，不自动覆盖。
- 缺测日不当作 0 降水；连续事件遇缺测日中断，避免制造虚假的干旱或低光照序列。
- 首版不静默插补。未来若提供插补，必须保存原值、方法、时间和 `quality_flag=imputed`。
- 覆盖率：`≥98%` 为良好，`95%–<98%` 为可用但提示，`<95%` 为低覆盖警告；统计仍可输出，但 Agent 必须在结论中提示不确定性。

## 5. 用户与任务调研

### 5.1 用户角色

| 角色 | 核心目标 | 关键页面行为 | 成功标准 |
|---|---|---|---|
| 农业生产管理者 | 快速判断近期环境与风险 | 选择地块/年份、查看指标与风险、下载报告 | 3 分钟内找到主要变化与对应证据 |
| 农业数据分析人员 | 确认数据质量和统计口径 | 导入 CSV、查看拒绝原因、运行分析、导出明细 | 每个指标可回溯到数据范围和算法口径 |
| 项目验收人员 | 验证功能完整性与结果一致性 | 核对 NASA provenance、复跑分析、比对 API/CSV/页面 | 相同输入和参数产生一致结果，来源可复现 |
| 平台运维人员 | 确保服务可用、任务可追踪 | 健康检查、查看任务状态和错误 | 故障能定位到请求、任务或导入批次 |

### 5.2 关键用户流程

1. 打开首页，看到数据范围、地块数、最新分析时间和质量状态。
2. 选择地块、年份或日期范围，页面所有图表和卡片同步刷新。
3. 导入 CSV，界面显示总行数、有效行、拒绝行、重复行、警告和原因分布。
4. 运行同步分析，成功后更新指标、风险和 Agent 上下文；失败任务保留错误摘要且不覆盖上次成功结果。
5. 用户可直接询问“最热的三个月”或“9 月到 11 月整体如何”；本地模型从相关月度/区间结构化上下文动态生成答复，并返回服务端证据卡。
6. 下载季节统计 CSV 和 Markdown 报告；在分析历史中可再次找到同一批结果。

## 6. 同类平台与布局调研

本节只提炼公开产品的交互模式，不宣称功能完全等价。

| 平台/资料 | 可观察的信息组织 | 对本项目的启发 | 不直接照搬之处 |
|---|---|---|---|
| NASA POWER Data Access Viewer | 地理位置、时间范围、参数选择和下载形成连续流程 | 将“筛选条件—图表—导出”保持在同一工作上下文；导出应继承筛选条件 | 本项目以地块为主，不需要复杂全球地图 |
| Copernicus Climate Data Store | 数据集目录、条件筛选、说明与下载分层 | 把数据口径和来源放在结果旁边；参数选择应可复现 | 不构建庞大的数据目录与账户工作流 |
| FAO WaPOR | 地图、指标、时间序列和下载围绕农业水生产率数据组织 | 风险、时间趋势和空间对象需要同步；农业界面应突出地块和周期 | 首版无遥感栅格，不用地图喧宾夺主 |
| WMO 气候实践指南 | 强调观测、质量控制、汇总和气候统计的一致性 | 质量摘要、样本数和口径必须与统计结果同时呈现 | 本项目不是国家气候业务系统，不宣称 WMO 认证 |

### 6.1 页面信息架构结论

采用“监测驾驶舱 + 可审计任务台”而不是通用后台模板：

1. **顶部状态条**：项目标题、服务状态、NASA POWER 正式数据来源链接、最新数据日期、最新分析时间。
2. **左侧筛选栏**：地块、年份、起止日期、季节；提供重置筛选。
3. **首屏指标卡**：平均温度、累计降水、平均光照、风险数；每张卡显示单位和相对变化。
4. **主分析区**：温度折线、降水柱状、光照面积图使用相同横轴和筛选条件。
5. **季节对比区**：四季卡片/表格，明确有效日数和覆盖率。
6. **质量与风险区**：并列呈现，避免用户只看到结论而忽略数据缺陷。
7. **Agent 证据区**：答复、引用指标、分析批次、建议追问分层显示。
8. **任务时间线**：导入、分析、导出动作按时间排序，显示成功/失败与文件链接。
9. **固定操作区**：导入数据、运行分析、导出 CSV、导出报告按钮可发现但不遮挡内容。

### 6.2 视觉与可用性结论

- 色彩使用森林绿、土壤米色、日照黄和雨水蓝；风险红/橙只表达状态，不作为装饰。
- 正文与背景对比度目标不低于 WCAG AA 常规文本要求；状态不能只靠颜色区分。
- 桌面采用 12 列响应式网格；小屏时筛选折叠为抽屉、卡片单列、表格可横向滚动。
- 图表必须有标题、单位、图例、空状态和数据点提示；禁止用假曲线填充空数据。
- 按钮使用动作型文字，如“运行季节分析”“导出当前筛选 CSV”，避免模糊的“确定”。
- 页面首次加载、导入、分析、失败、空数据均有明确反馈，杜绝点击后“没反应”。

## 7. 工程闭环方案

```text
NASA POWER Daily API / 用户 CSV
  → HTTP 响应体 JSON、查询 URL、哈希、参数和单位 provenance
  → 文件与字段校验
  → 行级质量检查及批次摘要
  → 原始观测持久化
  → 按地块/年份/季节聚合
  → 趋势、异常、风险事件
  → 按问题检索月度/季节/排名/区间/趋势/风险/来源上下文
  → qwen2.5:3b 动态生成回答和证据 ID
  → 服务端校验主题/月份/风险语义/指标数字并回填证据；失败才规则回退
  → 页面联动展示
  → CSV/Markdown 导出
  → 分析历史、参数和证据复核
```

闭环的关键不是步骤数量，而是每个产物都有标识和追踪关系：`import_id → observation → analysis_id → metric/risk → answer/export`。指标数字只能来自服务端证据 value；年份、月份、日期仅作为时间标识处理。普通对话重试后仍过长（`too_verbose`）或风险陈述与证据矛盾（`inconsistent_risk_claim`）时，记录原因并使用规则回退。复跑相同数据与参数应得到一致数值结果；失败任务保留错误摘要但不覆盖上一成功结果。

## 8. 已知限制与后续方向

1. 日尺度数据无法恢复小时极值或降雨历时。
2. 没有作物、品种、生育期、土壤、灌溉和管理措施时，只输出“环境风险提示”，不输出确定性农艺诊断。
3. 固定四季适合教学与通用比较，热带或南半球部署需要配置化。
4. IQR 对短序列和强季节性敏感，因此按地块与季节分组，并公开样本数。
5. 当前 Agent 已接入本地 `qwen2.5:3b`：模型负责理解问题和组织正文，统计、来源和证据仍由后端掌握；模型不可用或输出不受证据支持时返回规则答案。
6. NASA POWER 网格值不能替代地面站/田间传感器；若后续接入现场数据，需要在来源层明确区分并支持多来源对照。

### 9.1 调研证据到设计决策的追溯

| 证据 | 本项目采用的结论 | 落地位置 |
|---|---|---|
| 参考资料 1，WMO-No. 100 | 气候统计必须伴随时间范围、样本与质量口径，不能只给孤立平均值 | 本文 2.4、4；`REQUIREMENTS.md` FR-023/027；`DATA_DICTIONARY.md` 第 6 节 |
| 参考资料 2，WMO-No. 8 | 观测变量、单位和质量控制需有稳定定义 | 本文 2.2、4；`DATA_DICTIONARY.md` 第 1、4 节 |
| 参考资料 3，ETCCDI | 连续干日采用日降水 `<1 mm` 的通用指数惯例作为项目基线 | 本文 2.4、3；`ARCHITECTURE.md` 7.1/7.4 |
| 参考资料 4，FAO-56 | 温度、辐射、湿度、降水是农业环境/蒸散分析的重要气象输入；日辐射单位需明确换算 | 本文 2.1、2.2；`DATA_DICTIONARY.md` 派生字段 |
| 参考资料 5–6，FAO WaPOR | 农业对象、时间序列、指标和下载应在同一分析上下文中组织 | 本文 6、6.1；`REQUIREMENTS.md` FR-010/052 |
