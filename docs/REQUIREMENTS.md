| 属性 | 值 |
|---|---|

| 日期 | 2026-08-22 |

## 1. 产品目标

构建一个可独立运行的农田气象时序分析平台，使用户能够直接使用可追溯的 NASA POWER 正式公开日数据或导入自有 CSV，完成质量检查、季节统计、趋势与风险识别、本地模型动态问答、结果导出和历史复核。

### 1.1 可量化目标

1. 对温度、降水、太阳辐射三项核心变量实现按地块、日期、年份、季节的统一筛选和统计。
2. 导入结果能逐批次说明总行数、有效行、拒绝行、重复行和主要错误原因。
3. 任何风险或 Agent 结论都至少附带一个结构化数值证据和明确时间/地块范围。
4. 当前筛选结果可以导出为实际可打开的 CSV，最新分析可以导出为 Markdown 报告。
5. 分析任务可追踪、可复跑；失败不破坏上一成功结果。
6. 默认数据的提供方、API 版本、查询 URL、参数/单位、坐标、获取时间、原始文件和归一化文件哈希均可查询。
7. 本地模型回答不是固定模板：模型必须依据问题相关结构化上下文生成正文，所有数值和引用由服务端证据校验；失败才使用规则回退。

## 2. 范围

### 2.1 本期范围

- NASA POWER 2024 深圳光明、龙岗、大鹏三网格正式公开数据初始化与来源追溯。
- CSV 导入与字段、类型、范围、重复、缺失、连续性检查。
- SQLite 持久化。
- 概览指标、日序列、四季对比、趋势、统计异常和风险事件。
- 本地 `qwen2.5:3b` 基于问题相关结构化分析上下文动态生成中文回答，服务端证据映射、校验、重试与规则回退。
- 分析历史、任务状态和证据链。
- 当前筛选季节统计 CSV、最新分析 Markdown 报告导出。
- 响应式 Web 页面、空/加载/成功/失败状态。
- 自动化测试、启动脚本和工程文档。

### 2.2 明确不在本期范围

- 实时气象站协议、遥感栅格、地图 GIS 编辑。
- 作物产量预测、病害确诊、自动灌溉控制。
- 在缺少作物和土壤信息时输出确定性农艺处方。
- 多组织权限、收费、短信告警和公网高可用部署。
- 依赖云端大模型才能运行的核心能力。

## 3. 角色与权限边界

首版为本地单用户平台，不实现登录，但页面和接口仍按职责设计：

| 角色视角 | 主要能力 | 只读/写入 |
|---|---|---|
| 生产管理者 | 浏览、筛选、风险查看、问答、导出 | 读为主 |
| 数据分析人员 | 导入、运行分析、检查质量、导出 | 读写 |
| 验收人员 | 核对正式来源、复跑分析、查看历史、比对证据 | 只读及触发分析 |
| 运维人员 | 健康检查、任务错误、启动/停止 | 运维 |

未来引入认证时，写操作需按此边界授权；本期不得因无登录而省略输入校验和审计字段。

## 6. 关键业务规则

1. 默认只用 `quality_flag` 为有效状态的数据计算指标；被排除数量必须可见。
2. 缺测值不是 0；任何填充值必须带方法与质量标识。
3. 分析任务启动时固化筛选参数、阈值版本和观测范围。
4. 新分析失败时，首页仍显示上一成功分析，并显式提示本次失败。
5. CSV、页面和 Agent 使用同一服务层结果，禁止三套独立算法造成数值漂移。
6. 冬季跨年按 `season_year` 合并；筛选日历年时接口需公开使用的是日历范围还是季节年。
7. 风险阈值为可配置项目默认，不在页面中表达为普适农业标准。
8. NASA POWER 记录的空间语义是网格点产品，不写成地面站或田间实测；来源元数据与当前数据集一起暴露。
9. 模型不重算或写回统计；指标数字只能来自服务端证据 value；年份、月份、日期仅作为时间标识处理；最终证据只能由服务端目录生成。

## 7. 端到端验收场景

### AC-01 首次启动

**给定** 空数据库，**当** 执行启动脚本并访问首页，**那么**：

- 健康接口返回 `status=ok`；
- 页面有 NASA POWER 光明、龙岗、大鹏 3 个网格、2024 完整闰年和 1,098 条正式公开数据；
- `/api/data/source` 返回 POWER Daily API v2.9.7、三个查询 URL、期间、参数和哈希；
- 标题仅使用“农田气象时序分析 Agent”；
- 首页无 JavaScript 控制台致命错误。

### AC-02 合法 CSV 导入

**给定** 10 行合法数据，**当** 上传 CSV，**那么**生成唯一 `import_id`，显示 10 行有效、0 行拒绝，并能在观测查询中找到数据。

### AC-03 非法 CSV 质量反馈

**给定** 包含缺日期、负降水、湿度 120 和冲突重复的数据，**当** 上传，**那么**系统分别计数并返回行号示例；合法行仍可按明确策略写入，错误行不参与分析。

### AC-04 筛选联动

**给定** 多地块数据，**当** 只选择一个地块和夏季，**那么**指标卡、三张图、季节表、风险和导出均只含该范围。

### AC-05 季节与跨年冬季

**给定** 2025-12、2026-01、2026-02 数据，**当** 按冬季 2026 分析，**那么**三个月归入同一季节结果，日期和有效天数正确。

### AC-06 风险证据

**给定** 连续 7 日降水均小于 1 mm，**当** 运行分析，**那么**只生成一个 `DRY_SPELL` 事件，并返回地块、起止日、持续 7 日、累计降水和阈值。

### AC-07 Agent 可解释回答

**给定** 已成功分析和可用的 `qwen2.5:3b`，**当** 询问“请比较 12 个月，告诉我最热的三个月，并说明正式数据来自哪里”，**那么**模型动态给出 7、8、9 月及对应月均温，引用三条 `month.*` 证据和 `data.source`，且 `mode=local_model/fallback_used=false`。

### AC-08 导出一致性

**给定** 当前筛选为地块 PLOT-A、2026 年，**当** 导出 CSV 和报告，**那么**两个文件可打开、内容不为空，季节累计降水与页面/API 在允许舍入误差内一致。

### AC-09 失败可恢复

**给定** 已有成功分析 A，**当** 新分析 B 因参数错误失败，**那么**B 记录为失败并给出原因，A 仍可查看和导出，服务继续响应。

### AC-10 移动端与反馈

**给定** 390×844 视口，**当** 打开页面并执行分析，**那么**主要按钮可触达，筛选可展开，表格可滚动，点击后立即出现处理状态并最终显示结果。

### AC-11 模型失败回退

**给定** Ollama 断连、超时，或重试后输出仍包含无证据指标数字、缺少必要月份引用、普通对话超过 100 字（`too_verbose`）、风险陈述与 `risk.*` 状态/触发条件矛盾（`inconsistent_risk_claim`），**当** 提交问答，**那么**接口继续返回 HTTP 200 和规则答案，`agent_runtime.mode=rule_fallback`，并保存具体 `fallback_reason`；统计、导出与历史仍可用。年份、月份、日期只作为时间标识，不因其未出现在证据 value 中触发 `unsupported_numbers`。

## 8. 验收数据集要求

默认交付数据集必须满足：

- 来自 NASA POWER 官方接口，来源主页、文档和查询 URL 可访问；
- 覆盖 2024-01-01 至 2024-12-31、三个深圳网格、共 1,098 条；
- 四个参数与平台字段映射明确，太阳辐射换算公式公开；
- 三个 JSON 来源快照、归一化 CSV 和 provenance 一并交付，CSV SHA-256 固化；现有规范化快照与后续 HTTP 响应体捕获必须明确区分；
- 明确声明网格产品不等同于地面站/田间传感器实测。

隔离测试合成夹具另用于覆盖异常和边界，至少有意注入并记录：

- 一次高温事件；
- 一次强降雨事件；
- 一次 7 日连续干日；
- 一次连续低光照；
- 少量缺测、重复或范围异常，用于验证质量面板；
- 固定随机种子，保证测试可复现。

合成夹具不得被页面或报告描述为当前 NASA 正式数据；它只用于可复现测试、导入拒绝/告警和风险阈值边界。
